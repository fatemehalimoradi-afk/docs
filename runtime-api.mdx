`window.nameless` is for theme scripts and plugins, **never renderers**.

<Warning>
  Prefer [data attributes](/data-attributes) over `dispatch`. Use `dispatch` only for what attributes can't express, such as driving a bundle from an unrelated part of the page.
</Warning>

## Global surface

| Member | Notes |
| --- | --- |
| `ready` | `Promise<void>` that resolves once bundles are loaded |
| `subscribe("bundles", cb)` | Reads the views of drawn bundles. Returns an unsubscribe function |
| `snapshot` | The view each drawn bundle was last handed (`RendererView[]`) |
| `dispatch(type, payload)` | Changes a bundle's picks or adds it to the cart |
| `use(plugin)` | Registers [plugin hooks](/plugin-hooks) and [resolver stages](/resolver-stages) |
| `override` | `{ bundleId }` of the bundle bound to the theme's add-to-cart button, if any |
| `registerShopThemeScript(handlers)` | A shop's cart-drawer script — see [Shopify integration](/shopify-integration#after-add-to-cart) |

Members prefixed `__` are internal. `subscribe` and `use` are queued until the runtime installs, so script order doesn't matter.

## Reading state

```js
window.nameless.subscribe("bundles", function (views) {
  // called at once, then after every repaint of any bundle, and when one leaves the page
});
```

`views` are the [views](/renderer-view) drawn bundles were last handed, the same objects as `snapshot`. `"bundles"` is the only topic; undrawn bundles aren't listed.

## Dispatch actions

```js
var atc = await window.nameless.dispatch("addToCart", { bundleId: "…" });
```

| Action | Payload | Returns | Attribute equivalent |
| --- | --- | --- | --- |
| `quantityChange` | `{ bundleId, selectorId, quantity, productId?, variantId? }` | `DispatchResult` | `data-nameless-qty-selector` |
| `variantChange` | `{ bundleId, selectorId, variantId, productId? }` | `DispatchResult` | `data-nameless-variant-selector` |
| `optionChange` | `{ bundleId, selectorId, name, value, unit? }` | `DispatchResult` | `data-nameless-option-selector` |
| `chooseTier` | `{ bundleId, tierId }` | `DispatchResult` | `data-nameless-tier-id` |
| `selectionPlanChange` | `{ bundleId, changes: SelectionChange[] }` | `DispatchResult` | batch button |
| `sellingPlanChange` | `{ bundleId, selectorId, sellingPlanId, productId? }` | `DispatchResult` | `data-nameless-selling-plan-selector` |
| `sellingPlanGroupChange` | `{ bundleId, groupName }` | `DispatchResult` | `data-nameless-selling-plan-group-selector` |
| `sharedSellingPlanChange` | `{ bundleId, sellingPlanId }` | `DispatchResult` | `data-nameless-shared-selling-plan-selector` |
| `variantLineChange` | `{ bundleId, selectorId, productId, variantId, quantity }` | `DispatchResult` | `data-nameless-variant-line` |
| `loadMoreProducts` | `{ bundleId, selectorId }` | `Promise<DispatchResult>` | `data-nameless-load-more` |
| `addToCart` | `{ bundleId }` | `Promise<AddToCartResult>` | `data-nameless-atc` |

```ts
type DispatchResult = { ok: true } | { ok: false; code: string; message: string };

type AddToCartResult =
  | { ok: true; lines: Array<{ selectorId; variantId; quantity; sellingPlanId? }> }
  | {
      ok: false;
      code: string;
      message: string;
      shopperMessage?: string; // the cart's own sentence, already in the shopper's language
      unmetClauses?: Array<{ offerId: string; clauseId: string; selectorIds: string[] }>; // with UNMET_OFFER_CLAUSE
    };
// Both shapes can also carry pluginWarnings from plugin hooks.
```

- **`chooseTier`**: `TIER_NOT_CHOOSABLE` when the tier isn't chosen and its `ifChosen` is `null`.
- **`selectionPlanChange`**: sets several picks at once, keeping the chosen tier while still met. Each change is `{ selectorId, quantity, variantId?, productId? }`; at most 32, no repeated selector and product pair, else `INVALID_PAYLOAD`.
- **`sellingPlanChange`**: `sellingPlanId: null` is one-time. Refused while `view.subscriptions` is `null`, for a plan the chosen variant isn't sold on, with `UNKNOWN_SELECTOR` when nothing is picked on the row, and with `WRONG_SELECTOR_KIND` on a selector picked unit by unit.
- **`sellingPlanGroupChange`**: `groupName: null` is one-time. Refused while `view.subscriptions` is `null`, with `WRONG_SELECTOR_KIND` unless `sharedPlanOffered`, with `GROUP_NOT_SHARED` when any item can't be bought on the group, and with `UNKNOWN_SELECTOR` when nothing is selected.
- **`sharedSellingPlanChange`**: `null` is one-time. `PLAN_NOT_SHARED` for an id not in `sharedPlans`; otherwise refused like `sellingPlanGroupChange`.
- **`variantLineChange`**: `quantity: 0` removes the line; `WRONG_SELECTOR_KIND` unless the selector is a `"multi"` collection.
- **`addToCart`**: refused before the cart call with `EMPTY_SELECTION` while a row has no variant, and `UNMET_OFFER_CLAUSE` while an offer-wide condition isn't met (`unmetClauses` names them).
- Before the runtime installs, every action returns `{ ok: false, code: "NOT_READY", message }`: a promise of it for `addToCart` and `loadMoreProducts`, else a plain object.

Failure codes: `NOT_READY`, `UNKNOWN_ACTION`, `INVALID_PAYLOAD`, `INVALID_QUANTITY`, `UNKNOWN_BUNDLE`, `UNKNOWN_SELECTOR`, `UNKNOWN_VARIANT`, `UNKNOWN_TIER`, `TIER_NOT_CHOOSABLE`, `HANDLER_THREW`, `EMPTY_SELECTION`, `UNMET_OFFER_CLAUSE`, `VARIANT_UNAVAILABLE`, `CART_HTTP_ERROR`, `CART_REJECTED`, `PLUGIN_BLOCKED`, `WRONG_SELECTOR_KIND`, `UNKNOWN_SELLING_PLAN`, `SUBSCRIPTIONS_DISABLED`, `GROUP_NOT_SHARED`, `PLAN_NOT_SHARED`, `UNKNOWN_UNIT`, `AMBIGUOUS_PRODUCT_LINE`, `LOAD_FAILED`.

## Debugging

| Task | How |
| --- | --- |
| Host diagnostics | Console messages prefixed `[FastBundle]` (theme-button override: `[FastBundle:override]`) |
| Trace the theme-button override | Set `window.nameless.__overrideDebug = true` before adding to cart |
| Preview an inactive bundle | Append `?nameless_preview=true` to the product page URL. Adds at full price; the discount covers **Active** bundles only |
| Measure load timing | `performance.getEntriesByType("measure")`: `fastbundle:time-to-data`, `fastbundle:time-to-first-mount`, `fastbundle:time-to-first-render`, `fastbundle:paint` |
| Confirm the widget mounted | Look for `[data-nameless-block]` and `[data-nameless-widget="{id}"]` |

Logged codes you can act on: the `RENDERER_*` codes in [When things go wrong](/renderer-function#when-things-go-wrong), plus `BUNDLE_UNSELLABLE`, `ATC_OVERRIDE_EXCLUSIVE_SKIP`, and `CART_DRAWER_STEP_FAILED`. Include other codes when you contact support.

## Pre-ship checklist

### Renderer

- [ ] Follows [Register](/renderer-function#register) and [Hard rules](/renderer-function#hard-rules); every repeated element has an `id` from `view.bundleId`
- [ ] Handles empty `products` and `selections`, `null` images and money
- [ ] Collection rows carry `data-nameless-product-id`; one-product selectors don't
- [ ] Tier controls follow [Tier controls](/data-attributes#tier-controls); every ladder rung has its own
- [ ] Tier names from `requirements` with counts as `ctx.t` variables
- [ ] Add-to-cart and plan controls follow `view.addToCart` and `view.subscriptions`
- [ ] View strings escaped; every word through `ctx.t`; existing literals unchanged

### Styling

- [ ] Every rule under `[data-nameless-widget]`; no global element selectors, theme classes, or imports
- [ ] Classes match the renderer's; usable with CSS disabled

### Plugins

- [ ] `before` hooks return within 1500ms or tolerate being cut off
- [ ] Blocks use a meaningful `code` and a shopper-readable `message`
- [ ] `lineProperties` keyed by selector id; `__FB_ATC_UID` left alone
- [ ] Resolvers call `next()` and adjust
- [ ] Hook failures leave add-to-cart working
