title: "Runtime API"
description: "Read bundle state from outside the widget, debug, and ship"

Theme scripts and plugins — **never renderers** — can talk to the runtime on `window.nameless`.

<Warning>
  Prefer the [data attributes](/data-attributes) over `dispatch`. Every interaction already has a supported path: put the right `data-nameless-*` attribute on the right element and let the runtime drive it. That path is the contract we test and keep stable.

  Inside a renderer, `dispatch` is **forbidden outright**. In other scripts, treat it as a last resort for cases the attributes can't express — for example, a bundle driven from an unrelated part of the page. Reading state with `subscribe` carries none of these caveats.
</Warning>

## Global surface

| Member | Notes |
| --- | --- |
| `ready` | `Promise<void>` that resolves once bundles are loaded |
| `subscribe("bundles", cb)` | Reads the views of drawn bundles. Returns an unsubscribe function |
| `snapshot` | The view each drawn bundle was last handed (`RendererView[]`) |
| `dispatch(type, payload)` | Changes a bundle's picks or adds it to the cart |
| `use(plugin)` | Registers [plugin hooks](/plugin-hooks) and [resolver stages](/resolver-stages) |
| `override` | `{ bundleId }` of the bundle bound to the theme's add-to-cart button, when one is |
| `registerShopThemeScript(handlers)` | A shop's cart-drawer script — see [Shopify integration](/shopify-integration#after-add-to-cart) |

Anything on `window.nameless` prefixed with `__` is internal — don't build against it. A pre-install shim queues `subscribe` and `use` until the runtime installs, so script order doesn't matter.

## Reading state

```js
window.nameless.subscribe("bundles", function (views) {
  // called at once, then after every repaint of any bundle, and when one leaves the page
});
```

`views` holds the [view](/renderer-view) each drawn bundle was last handed — the same objects as `window.nameless.snapshot`. `"bundles"` is the only topic. A bundle no widget draws is not listed. Branch on `view.viewVersion`.

You read views, never engine state or the bundle's rules.

## Dispatch actions

```js
var result = window.nameless.dispatch("chooseTier", { bundleId: "…", tierId: "…" });

var atc = await window.nameless.dispatch("addToCart", { bundleId: "…" });
```

| Action | Payload | Returns | Attribute equivalent |
| --- | --- | --- | --- |
| `quantityChange` | `{ bundleId, selectorId, quantity, productId?, variantId? }` | `DispatchResult` | `data-nameless-qty-selector` |
| `variantChange` | `{ bundleId, selectorId, variantId, productId? }` | `DispatchResult` | `data-nameless-variant-selector` |
| `optionChange` | `{ bundleId, selectorId, name, value, unit? }` | `DispatchResult` | `data-nameless-option-selector` |
| `chooseTier` | `{ bundleId, tierId }` | `DispatchResult` | `data-nameless-tier-id` |
| `selectionPlanChange` | `{ bundleId, changes: SelectionChange[] }` | `DispatchResult` | batch button |
| `sellingPlanChange` | `{ bundleId, selectorId, sellingPlanId, productId? }` | `DispatchResult` | `data-nameless-selling-plan-selector` |
| `sellingPlanGroupChange` | `{ bundleId, groupName }` | `DispatchResult` | `data-nameless-selling-plan-group-selector` |
| `loadMoreProducts` | `{ bundleId, selectorId }` | `Promise<DispatchResult>` | `data-nameless-load-more` |
| `addToCart` | `{ bundleId }` | `Promise<AddToCartResult>` | `data-nameless-atc` |

```ts
type DispatchResult = { ok: true } | { ok: false; code: string; message: string };

type AddToCartResult =
  | { ok: true; lines: Array<{ selectorId; variantId; quantity; sellingPlanId? }> }
  | {
      ok: false;
      code: string;
      message: string;
      shopperMessage?: string; // the cart's own sentence, already in the shopper's language
    };
// Both shapes can also carry pluginWarnings from plugin hooks.
```

Behavior worth knowing:

- **`chooseTier`** is the whole message: the engine makes the smallest change to the picks that meets the tier. It refuses with `TIER_NOT_CHOOSABLE` when the tier isn't chosen and still wouldn't apply (its `ifChosen` is `null`). One chosen tier per offer: choosing one replaces the offer's choice, choosing it again clears it, and any change that stops it applying drops it.
- **`selectionPlanChange`** sets several picks at once and keeps the chosen tier while the picks still meet it. Each change is `{ selectorId, quantity, variantId?, productId? }`; at most 32, with no selector and product pair twice, or the action fails with `INVALID_PAYLOAD`. To also choose a tier, send `chooseTier` next.
- **`sellingPlanChange`** sets one item's plan; `sellingPlanId: null` means one-time. Refused while `view.subscriptions` is `null`, for a plan the chosen variant isn't sold on, with `UNKNOWN_SELECTOR` when nothing is picked on the row, and with `WRONG_SELECTOR_KIND` on a selector picked unit by unit.
- **`sellingPlanGroupChange`** puts every selected item on one selling-plan group, each resolving its own plan in it; `groupName: null` means one-time. Groups match by name, since plan ids differ per variant. Refused while `view.subscriptions` is `null`, with `WRONG_SELECTOR_KIND` unless `sharedPlanOffered`, whole with `GROUP_NOT_SHARED` when any selected item can't be bought on that group, and with `UNKNOWN_SELECTOR` when nothing is selected.
- Before the runtime installs, every action returns `{ ok: false, code: "NOT_READY", message }` — as a plain object, except `addToCart`, which returns a promise of it.

Failure codes: `NOT_READY`, `UNKNOWN_ACTION`, `INVALID_PAYLOAD`, `INVALID_QUANTITY`, `UNKNOWN_BUNDLE`, `UNKNOWN_SELECTOR`, `UNKNOWN_VARIANT`, `UNKNOWN_TIER`, `TIER_NOT_CHOOSABLE`, `HANDLER_THREW`, `EMPTY_SELECTION`, `VARIANT_UNAVAILABLE`, `SOLD_OUT`, `CART_HTTP_ERROR`, `CART_REJECTED`, `PLUGIN_BLOCKED`, `WRONG_SELECTOR_KIND`, `UNKNOWN_SELLING_PLAN`, `SUBSCRIPTIONS_DISABLED`, `GROUP_NOT_SHARED`, `UNKNOWN_UNIT`, `LOAD_FAILED`.

## Debugging

| Task | How |
| --- | --- |
| See host diagnostics | Console messages prefixed `[nameless]` |
| Trace the theme-button override | Set `window.nameless.__overrideDebug = true` before adding to cart |
| Preview an inactive bundle | Append `?nameless_preview=true` to the product page URL. Preview skips the browser cache and sends no analytics. The checkout discount only covers **Active** bundles, so a previewed bundle adds at full price |
| Measure load timing | `performance.getEntriesByType("measure")` — entries `nameless:time-to-data`, `nameless:time-to-first-mount`, `nameless:time-to-first-render`, `nameless:paint` |
| Confirm the widget mounted | Look for `[data-nameless-block]` and `[data-nameless-widget="{id}"]` |
| Inspect current state | `window.nameless.subscribe("bundles", console.log)` |

Codes the host logs with the `[nameless]` prefix include `BOOT_BUNDLES_NOT_ARRAY`, `NORMALIZE_FAILED`, `ENGINE_CREATE_FAILED`, `DISPATCH_UNKNOWN_BUNDLE`, `BUNDLE_UNSELLABLE`, `ATC_OVERRIDE_EXCLUSIVE_SKIP`, `DISCOUNT_ENGINE_MISSING`, `PRESENTMENT_RATE_UNAVAILABLE`, `RENDERER_MOUNT_NOT_FOUND`, `RENDERER_THREW`, `RENDERER_LOAD_ERROR`, `RENDERER_VIEW_VERSION_MISSING`, `RENDERER_VIEW_UNSUPPORTED`, and `CART_DRAWER_STEP_FAILED`. Theme-button override messages use the `[nameless:override]` prefix. `PLUGIN_BLOCKED`, `CART_HTTP_ERROR`, and `CART_REJECTED` are add-to-cart result codes, not log entries.

## Pre-ship checklist

### Renderer

- [ ] `defineRenderer(fn, { viewVersion: 2 })` called once, at top level, unguarded
- [ ] Reads only `ctx.view` (plus `ctx.t`, `ctx.locale`, `ctx.productUrl`, `ctx.collectionUrl`) and paints with `ctx.paint(html)`
- [ ] Rebuilds everything from the view on every call; no cached nodes, no accumulated state
- [ ] Every repeated element has an `id` built from `view.bundleId` and its own id
- [ ] No listeners, no `dispatch`, no `fetch`, no globals
- [ ] No money arithmetic, no counting, no eligibility logic: prices are `Money.text`, counts are `summary.unitCount`, tier facts come from `view.tiers`
- [ ] Branches on `itemType` and `type`; a collection selector with `asPageProduct` is drawn like a product selector, without `data-nameless-product-id`
- [ ] Handles empty `products`, empty `selections`, `null` images, and `null` money
- [ ] Unpicked products show their `defaultVariantId` variant; quantities shown are `selection.quantity`
- [ ] Collection rows carry both the selector id and `data-nameless-product-id`; a load-more button follows them while `moreProducts` is not `none`
- [ ] Tier controls carry only `data-nameless-tier-id`, are drawn as controls only when `ifChosen` is set or the tier is chosen, and every rung of a ladder has its own
- [ ] Tier names come from `requirements` with counts as `ctx.t` variables; reward sentences from `outcome`
- [ ] Add-to-cart button only when `themeButtonAdds` is false, with its disabled, busy, and error states drawn from `view.addToCart`
- [ ] No plan control while `view.subscriptions` is null; per-item plans from each item's own variant; no plan preselected
- [ ] Every view string escaped; every word you write through `ctx.t` (and not escaped); existing `ctx.t` literals unchanged

### Styling

- [ ] Every rule scoped under `[data-nameless-widget]`
- [ ] No global element selectors, no theme classes, no external imports
- [ ] Class vocabulary matches the renderer exactly
- [ ] Markup still readable and operable with the CSS disabled

### Plugins

- [ ] `before` hooks return within 1500ms, or tolerate being cut off
- [ ] Blocks use a meaningful `code` and a shopper-readable `message`
- [ ] `lineProperties` keyed by selector id; `__FB_ATC_UID` left alone
- [ ] Resolvers call `next()` and adjust, rather than replacing a stage wholesale
- [ ] No `dispatch` calls that a `data-nameless-*` attribute could have handled
- [ ] Hook failures verified to leave the shopper's add-to-cart working
