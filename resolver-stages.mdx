---
title: "Resolver stages"
description: "Wrap the pipeline that lets the theme's add-to-cart button add the bundle"
---

When a bundle's add-to-cart method is the **theme button**, the host intercepts the theme's add and adds the bundle's lines instead. You can wrap each **resolver stage** of that pipeline:

```js
window.nameless.use({
  atcOverride: {
    async resolveProductSelection(ctx, next) {
      var base = await next(); // the built-in behavior
      return Object.assign({}, base, { quantity: 2 });
    },
    shouldOverride(ctx, next) {
      return ctx.trigger === "click" ? next() : false;
    },
  },
});
```

Stages, in order:

| Stage | Purpose | Default return | Timeout |
| --- | --- | --- | --- |
| `resolveTargetForm` | Locate the theme's product form | `HTMLFormElement` or `null` | 1500ms |
| `resolveProductSelection` | Read variant, quantity, and selling plan from the form | `{ variantId?, quantity?, productId?, sellingPlanId? }` | 1500ms |
| `shouldOverride` | Decide whether to swap this add request | `true` (must return a boolean) | 1500ms |
| `buildPayload` | Build the cart payload from bundle state | `{ ok, items, lines, … }` | 500ms |
| `transformCartRequest` | Rewrite the `/cart/add.js` request body | rebuilt request | 500ms |
| `runPostAdd` | Post-add side effects on an intercepted fetch or XHR add; the default opens no drawer | `void` | 1500ms |
| `transformCartResponse` | Rewrite the cart response. Single-item request bodies only | synthesized response | 500ms |

On the internal path (Fast Bundle 2.0 adding the bundle itself), `runPostAdd` and `transformCartResponse` don't run.

Every resolver receives `(ctx, next)`:

| `ctx` field | Meaning |
| --- | --- |
| `bundleId` | Bundle being added |
| `pageProductId` | The product page's product id |
| `pdpCoupledSelectorIds` | Selectors coupled to the page product |
| `trigger` | `"click"`, `"full-page"`, or `"fallback"` |
| `transport` | `"fetch"`, `"xhr"`, or `"internal"` |
| `stage` | Qualified stage name, e.g. `atcOverride:buildPayload` |
| `form`, `selection`, `request`, `payload`, `response` | Set once produced |
| `debug`, `log` | Debug flag and logger, driven by `window.nameless.__overrideDebug` |

Call `next()` and adjust its result; don't reimplement a stage. A resolver that throws, times out, or returns a rejected shape falls through to `next()` with a warning.

Timeouts include your `next()` call. With a `buildPayload` resolver registered, `addToCart.before` [plugin hooks](/plugin-hooks) share its 500ms budget.

## When the override runs

Only after the widget draws successfully, and when all hold:

1. The add-to-cart method is the theme button, or the page is the bundle's own [Bundle as Product](/shopify-integration#bundle-as-product) page. Never in a popup.
2. The page has a product.
3. A selector matches the page's product, or the page is the bundle's own product page.

Only the first bundle in display order takes the theme button; others that would aren't drawn (`ATC_OVERRIDE_EXCLUSIVE_SKIP`).

## Coupling to the page's product

The theme form's variant and quantity feed the selectors standing for the page's product. Not coupled:

- a selector listing a collection's products, even one containing the page's product;
- a selector picked unit by unit;
- a product selector pinned to one variant;
- any selector, when the widget itself picks the page product's quantity and variant.

The view already reflects the theme form's variant and quantity. On the bundle's own Bundle as Product page, quantity N adds N discounted copies of the bundle's lines.

## Supported shapes

| Shape | Supported |
| --- | --- |
| A product selector for the page's product, plus collection picks from the widget | Yes — the main use case |
| A collection selector drawn as the page's product | Yes |
| Only a product selector for the page's product | Yes |
| The page's product only inside a collection list | No — it isn't added; give it its own product selector |

If the bundle's lines can't be built, the theme's add goes through unchanged, unless the widget picks the quantity itself: then the add is refused and the widget says why. If Shopify refuses the lines or adds fewer, the widget shows Shopify's message. A subscription plan picked in the theme form is refused (`SUBSCRIPTIONS_DISABLED`) when the bundle doesn't sell subscriptions.
