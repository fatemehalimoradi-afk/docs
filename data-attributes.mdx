The runtime wires these attributes after each paint. Controls inside a disabled `<fieldset>`, or carrying `disabled` or `aria-disabled="true"`, are ignored.

## Core attributes

| Attribute | Element | Value | Behavior |
| --- | --- | --- | --- |
| `data-nameless-variant-selector` | `<select>` | `selector.id` | On `change`, picks the variant in `select.value` |
| `data-nameless-option-selector` | `<select>` | `selector.id` | On `change`, picks one option value (see [option dropdowns](#option-dropdowns)) |
| `data-nameless-option-name` | the same `<select>` | `option.name`, e.g. `Size` | Names the option |
| `data-nameless-unit` | the same `<select>` | the unit's index | The unit it picks for; without it, every unit of the row |
| `data-nameless-qty-selector` | input or button (see [patterns](#quantity-and-tier-patterns)) | `selector.id` | Sets a quantity, by element type |
| `data-nameless-product-id` | each control on a collection row | `product.id` | Which product changed. Required on collection rows |
| `data-nameless-tier-id` | any element standing for one tier | `tier.id` | On `click`, chooses that tier |
| `data-nameless-load-more` | `<button>` after a collection's rows | `selector.id` | On `click`, loads the next batch of products |
| `data-nameless-variant-line` | `<button>` or `<select>` on a collection row | `selector.id` | Adds, steps, or removes one variant line (see [variant lines](#variant-lines)) |
| `data-nameless-variant-id` | a variant-line `<button>` | the variant's `id` | Which variant line the button steps |
| `data-nameless-atc` | `<button>` | `view.bundleId` | On `click`, adds the bundle to the cart |
| `data-nameless-selling-plan-selector` | `<select>` | `selector.id` | On `change`, sets the item's selling plan; `""` is one-time |
| `data-nameless-selling-plan-group-selector` | `<select>` or checkbox | (no value) | On `change`, puts every item on the selected group; `""` or unticked is one-time |
| `data-nameless-shared-selling-plan-selector` | `<select>` or checkbox | (no value) | On `change`, puts every item on the selected plan (a `view.subscriptions.sharedPlans[].id`); `""` or unticked is one-time |
| `data-nameless-theme-atc` | `<button>` | (no value) | On `click`, submits the theme's product form. Shopify theme only, while `view.addToCart.themeButtonAdds` is true |

## Quantity and tier patterns

| Pattern | Markup | Behavior |
| --- | --- | --- |
| **Number input** | `<input type="number" min="0" step="1" data-nameless-qty-selector="{selector.id}">` | On `change`, sets the whole number in the field. Empty or invalid sets the larger of `min` and `1` |
| **Quantity card** | `<button type="button" data-nameless-qty-selector="{selector.id}" value="{qty}">` | On `click`, sets `value`, or `0` if the quantity already equals it. Set `aria-pressed` yourself |
| **Optional add-on** | One checkbox **and** one number input with the same selector id (and product id on collection rows) | Unchecking sets `0` and remembers the number; checking restores it |
| **Tier control** | Any element with `data-nameless-tier-id="{tier.id}"` | On `click`, chooses the tier. Set `aria-pressed="true"` when `tier.state === "applied"` |
| **Batch button** | `<button type="button">` with **no** tier id, holding two or more `<input type="hidden" data-nameless-qty-selector="{selector.id}" value="{qty}">` with distinct selector ids | On `click`, sets every listed quantity at once. The attribute goes on the hidden inputs, **never** the button |

### Tier controls

A tier control carries only the tier id — no hidden quantity inputs. The engine makes the smallest change that meets the tier: on a one-product selector it raises or lowers the quantity; on a collection selector it adds to the first picked item or takes from the last. Tapping the chosen tier clears the choice. One chosen tier per offer; choosing another replaces it, and a change that stops it applying drops it.

Add the attribute only when `tier.ifChosen` is not `null` or `tier.chosen` is true; otherwise draw the tier as information. Draw it `disabled` when `tier.inStock` is false.

Controls inside a tier card keep their own click; only a click on the card itself chooses the tier. Never put `data-nameless-tier-id` and `data-nameless-atc` on one element: the tier click wins and nothing is added.

## Option dropdowns

One `<select>` per entry in `product.options`, instead of a variant `<select>`:

```html
<select data-nameless-option-selector="{selector.id}" data-nameless-option-name="Size">
  <option value="S">S</option>
  <option value="M" selected>M</option>
</select>
```

- `<option value>` is the **option value**, not a variant id. Mark selected what `selector.optionPicks` holds.
- On `change`, the selection becomes the one variant carrying every picked value, or none. A value with no purchasable variant stays selectable.
- Use one shape per selector.
- With `selector.unitPicks` set, draw one line per unit and add `data-nameless-unit="{index}"` to each dropdown.
- For one-product selectors only. On collection rows, use a variant `<select>`.

## Variant lines

On a collection selector with `type: "multi"`, one product can hold several **variant lines** (e.g. 2 × Red and 1 × Blue):

| Markup | Behavior |
| --- | --- |
| `<button type="button" data-nameless-variant-line="{selector.id}" data-nameless-product-id="{product.id}" data-nameless-variant-id="{variant.id}" value="+1">` | `+1` / `-1` steps that variant's line; a whole number sets it; `0` removes only that variant |
| The same button without `data-nameless-variant-id`, `value="0"` | Removes every line of the product |
| `<select data-nameless-variant-line="{selector.id}" data-nameless-product-id="{product.id}">` with an empty placeholder option and variant ids as values | Adds one unit of the chosen variant, then resets to the placeholder |

With several lines, a product-level quantity or variant control is refused with `AMBIGUOUS_PRODUCT_LINE` (quantity `0` still removes all lines). Draw each line from `selector.selections` by `productId` and `variantId`, with both in its `id`.

## Placement rules

- **One-product selectors** (`itemType: "product"`, or `asPageProduct: true`): one variant `<select>` (or one set of option dropdowns) and one quantity control, with **no** `data-nameless-product-id`.
- **Collection rows** (`asPageProduct: false`): every control on a row carries **both** the selector id and `data-nameless-product-id="{product.id}"`.
- Changing the variant of an **unpicked** collection row picks it with quantity 1. Raising a row's quantity from `0` needs no variant; the runtime uses the existing selection or `defaultVariantId`.
- Pair one checkbox with one number input per add-on.

## Add-to-cart and selling-plan controls

See [Add-to-cart button](/renderer-function#add-to-cart-button) and [Subscriptions](/renderer-view#subscriptions). Add `data-nameless-product-id` to plan selects on collection rows. A selector picked unit by unit can't take a per-item plan.

## Refused add-to-cart event

When add to cart (including the theme's button) is refused for a missing pick, the host dispatches a non-bubbling `nameless:add-to-cart-refused` `CustomEvent` on `[data-nameless-widget="{bundleId}"]`, for page scripts to point the shopper at the pick.
