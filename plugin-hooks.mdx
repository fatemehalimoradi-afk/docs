---
title: "Plugin hooks"
description: "Observe, block, or annotate add-to-cart from a storefront script"
---

Plugins run around add-to-cart from a storefront script — **not** the renderer.

## Registering

```js
window.nameless.use({
  addToCart: {
    before(ctx) {
      /* … */
    },
    after(ctx) {
      /* … */
    },
  },
});
```

`use()` returns an unsubscribe function (a plugin registered before the runtime installs can't be removed). Plugins run for every bundle; branch on `ctx.bundleId`.

## `addToCart.before`

Runs after the picks validate, before the cart request.

| Context field | Type |
| --- | --- |
| `bundleId` | `string` |
| `snapshot` | `{ bundleId: string }` — for prices or picks, [subscribe to the view](/runtime-api#reading-state) |
| `lines` | `Array<{ selectorId, variantId, quantity, sellingPlanId? }>` — `sellingPlanId` only on a subscription line |

Return one of:

```ts
undefined                                                   // no opinion
{ ok: true, lineProperties?: { [selectorId]: { [k]: string } } }
{ ok: false, code: string, message: string }                // blocks the add
```

A block ends the add with `PLUGIN_BLOCKED` and message `"{code}: {message}"`; later `before` hooks are skipped.

`lineProperties` are keyed by **selector id** and become line-item `properties` on every cart line of that selector. Hooks merge; later hooks win per key. Prefix `_` to hide a key on themes that hide underscore properties.

<Warning>
  Never set `__FB_ATC_UID`. Fast Bundle 2.0 overwrites it on lines a tier priced; on other lines it would confuse the discount function.
</Warning>

## `addToCart.after`

Runs only after a **successful** add. The cart drawer and `dispatch("addToCart")` wait for every `after` hook. Same context plus:

```ts
result: { ok: true; lines: Array<{ selectorId, variantId, quantity, sellingPlanId? }> };
```

Return nothing or `{ warnings: string[] }` (returned as `pluginWarnings`). It can't change the outcome.

## Execution semantics

| Behavior | Detail |
| --- | --- |
| Order | Sequential, in registration order |
| Timeout | 1500ms per hook (`before` and `after`). Exceeding it logs `HOOK_TIMEOUT` and moves on |
| Thrown errors | Logged (`[FastBundle/plugins]`) as `HOOK_THREW` and skipped |
| Bad return values | Anything but a plain object or `undefined` is ignored and reported as `HOOK_INVALID_RESULT` in `pluginWarnings` |
| Blocking | Only an explicit `{ ok: false }` halts the pipeline |

## Worked example

```js
window.nameless.use({
  addToCart: {
    async before(ctx) {
      if (!(await isEligible(ctx.bundleId))) {
        return { ok: false, code: "NOT_ELIGIBLE", message: "Bundle not available for you." };
      }
      var props = {};
      ctx.lines.forEach(function (line) {
        props[line.selectorId] = { _loyalty_ref: currentMemberId() };
      });
      return { ok: true, lineProperties: props };
    },
    after(ctx) {
      if (ctx.result.ok) {
        analytics.track("bundle_added", {
          bundleId: ctx.bundleId,
          items: ctx.result.lines.length,
        });
      }
    },
  },
});
```
