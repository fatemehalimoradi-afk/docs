---
title: "Plugin hooks"
description: "Observe, block, or annotate add-to-cart from a storefront script"
---

Plugins are for logic *around* the cart: eligibility gating, analytics, loyalty references, custom line-item properties. They live in a script you load on the storefront — **not** in the bundle's renderer.

## Registering

```js
window.nameless.use({
  addToCart: {
    before(ctx) {
      /* … */
    },
    after(ctx) {
      /* … */
    },
  },
});
```

`use()` returns an unsubscribe function. You can call it before the runtime has installed: a pre-install shim queues plugins and replays them at install, so script order doesn't matter. A plugin registered before install can't be removed afterwards. `window.nameless.ready` resolves once bundles are loaded, if you need to wait for state rather than just register.

Plugins are global: they run for every bundle on the page. Branch on `ctx.bundleId` when a hook is for one bundle.

## `addToCart.before`

Runs after the picks validate, before the cart request. It can **block** the add or **attach line properties**.

| Context field | Type |
| --- | --- |
| `bundleId` | `string` |
| `snapshot` | `{ bundleId: string }` |
| `lines` | `Array<{ selectorId, variantId, quantity, sellingPlanId? }>` — `sellingPlanId` only on a subscription line |

`snapshot` carries the bundle id only. To read prices or picks, subscribe to the bundle's [view](/runtime-api#reading-state).

Return one of:

```ts
undefined                                                   // no opinion
{ ok: true, lineProperties?: { [selectorId]: { [k]: string } } }
{ ok: false, code: string, message: string }                // blocks the add
```

A block ends the add with dispatch code `PLUGIN_BLOCKED` and the message `"{code}: {message}"`; the remaining `before` hooks are skipped.

`lineProperties` are keyed by **selector id** and land on every cart line of that selector as Shopify line-item `properties`. Multiple hooks merge; later hooks win per key. Prefix a key with `_` to keep it hidden from the shopper on themes that hide underscore properties.

<Warning>
  Never set `__FB_ATC_UID`. Knit writes it after your hooks run on every line a tier priced, replacing yours; on any other line your value would reach checkout and confuse the discount function.
</Warning>

## `addToCart.after`

Runs only after a **successful** add — never after a block, a failed validation, or a cart refusal. It is awaited: the cart drawer opens, and `dispatch("addToCart")` resolves, only after every `after` hook returns (each still capped at 1500ms). Same context plus `result`:

```ts
result: { ok: true; lines: Array<{ selectorId, variantId, quantity, sellingPlanId? }> };
```

Return nothing, or `{ warnings: string[] }`. Warnings come back on the add-to-cart result as `pluginWarnings`. You can't change the outcome from here.

## Execution semantics

| Behavior | Detail |
| --- | --- |
| Order | Sequential, in registration order — never parallel |
| Timeout | 1500ms per hook. Exceeding it logs `HOOK_TIMEOUT` and moves on |
| Thrown errors | Logged as `HOOK_THREW` and skipped — they never break the shopper's add-to-cart |
| Bad return values | Anything that isn't a plain object or `undefined` logs `HOOK_INVALID_RESULT` and is ignored |
| Blocking | Only an explicit `{ ok: false }` halts the pipeline |
| Mid-run changes | Hooks registered or removed during a run don't affect that run |

Because slow hooks are cut off at 1500ms, keep network calls out of `before`, or accept that a slow response counts as "no opinion".

## Worked example

```js
window.nameless.use({
  addToCart: {
    async before(ctx) {
      if (!(await isEligible(ctx.bundleId))) {
        return { ok: false, code: "NOT_ELIGIBLE", message: "Bundle not available for you." };
      }
      var props = {};
      ctx.lines.forEach(function (line) {
        props[line.selectorId] = { _loyalty_ref: currentMemberId() };
      });
      return { ok: true, lineProperties: props };
    },
    after(ctx) {
      if (ctx.result.ok) {
        analytics.track("bundle_added", {
          bundleId: ctx.bundleId,
          items: ctx.result.lines.length,
        });
      }
    },
  },
});
```
