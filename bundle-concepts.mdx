Knit is fully customizable. You do not pick a bundle type. You assemble each offer yourself: **product sets**, **conditions**, and **rewards** for the logic, and the **widget** (renderer and CSS) for how it looks and behaves on the storefront.

This page is how the logic pieces connect. You combine them however the offer needs.

## How the pieces connect

**Product sets** are the products in the offer — Set #1, Set #2, and so on.

**Conditions** and **rewards** attach to those sets. A condition counts items from a set (when this tier applies). A reward discounts a set (what the shopper gets, and on which products). Neither piece stands alone: every condition and every reward **names a product set**.

You choose the rest:

- One set or several
- One condition or several on the same card (all must be true)
- The discount on the same set as the condition, or on a different set
- As many **condition-reward** cards as you need — each card is one tier

The combination is the offer. The examples below are assemblies, not the only shape a Knit bundle can take.

<Steps>
  <Step title="Product sets">
    Name the products in play. Each set is one product, or a collection.
  </Step>
  <Step title="Conditions">
    Attach quantity rules to those sets: *Customer buys at least 2 items from Set #1*.
  </Step>
  <Step title="Rewards">
    Attach discounts to those sets: *Customer gets 19% off Set #1* — or off a different set.
  </Step>
  <Step title="Widget">
    Customize the renderer and CSS so the storefront matches the brand. Product sets, conditions, and rewards stay the source of truth for who qualifies and what is discounted.
  </Step>
</Steps>

## Example: volume on one product

Buy 2 of this shampoo, save 19%.

| Piece | In the editor |
| --- | --- |
| Product set | Set #1: **Single Product** → the shampoo |
| Condition | Customer buys **at least 2** items from **Set #1** |
| Reward | Customer gets **19%** discount on **Set #1** |

The widget can show on that shampoo’s page. At checkout, 19% off applies when the quantity is 2 or more.

The condition and the reward both name Set #1. Change only the product set, and the same “buy 2, 19% off” becomes a different offer:

| You want | Set #1 | What the shopper does |
| --- | --- | --- |
| Volume on one product | **Single Product** → the shampoo | Buy 2 of that shampoo |
| Same volume on every product in a collection | **Single Product (Collection-backed)** → Basics | Buy 2 of *the product they are viewing* (if it is in Basics). They are not mixing products. |
| Mix and match | **Shopify Collection** → Basics | Pick any products from Basics. Quantity 2 is the **total** across those picks. |

Volume vs mix and match is not a type you pick. It is one way of combining the same pieces.

## Example: discount a different set

The reward can point at a **different** set than the condition.

Buy the phone, get 20% off a case:

| Piece | In the editor |
| --- | --- |
| Set #1 | **Single Product** → the phone |
| Set #2 | **Shopify Collection** → cases |
| Conditions | at least 1 from Set #1 **and** at least 1 from Set #2 |
| Reward | 20% off **Set #2** |

The phone is required. The discount lands on the case. Two conditions on the same card must **both** be true.

## More than one tier

**Add new condition-reward** adds the next card against the **same** product sets.

- Card 1: at least 2 from Set #1 → 19% off Set #1
- Card 2: at least 4 from Set #1 → 25% off Set #1

Knit checks each card. The shopper gets the reward for the tier they meet.

## Product sets

Each set has an **Included item** type.

### Single Product

You pick **one product**. Use this when the offer is that exact item.

The shopper sees that product (variant + quantity). The widget can show on **that product’s page**.

### Single Product (Collection-backed)

You pick a **collection**, not one product. Use this when the same volume offer should run on every product in a collection, without adding each product by hand.

On a product page, Knit uses **the product the shopper is viewing**, but only if it is in that collection. The shopper is still buying **that one product**. If the page product is not in the collection, this set does not apply on that page.

### Shopify Collection

You pick a **collection**. The shopper can choose **more than one product** from it.

The widget lists products from the collection. Quantity on each row starts at 0 until the shopper adds it. Quantity and discount rules apply across those picks.

### How to choose

| You want | Use |
| --- | --- |
| One specific product | **Single Product** |
| Same volume offer on every product in a collection, one product per page | **Single Product (Collection-backed)** |
| Shopper mixes several products from a collection | **Shopify Collection** |

You can combine sets. Example: **Single Product** for a hero item, plus **Shopify Collection** for add-ons.

## Conditions

A condition is: **Customer buys** this many **items from** a product set.

| Comparison | Meaning | Example |
| --- | --- | --- |
| **at least** | This number or more | Buy 2 or more |
| **at most** | This number or fewer | Buy no more than 5 |
| **exactly** | This number only | Buy exactly 2 |
| **between** | An inclusive range | Buy 2–4 |

What “items from” means depends on the set:

- **Single Product** and **Single Product (Collection-backed)** — units of that one product.
- **Shopify Collection** — total units the shopper picked from the collection.

## Rewards

A reward is: **Customer gets** this **discount on** a product set.

**Percentage** — a percent off those items (0–100). Example: 19% off.

**Fixed amount** — a money amount off, in your shop currency. Then choose how it spreads:

| Mode | Meaning |
| --- | --- |
| **Total** | The amount off the qualifying items as a group, once. 10 off on two product sets is 10 off the combined subtotal. |
| **Per selector** | The amount off each product set you attached the reward to. 10 off on two product sets is 20 off. |
| **Per unit** | The amount off each unit in those product sets. 5 off with quantity 3 is 15 off. |

The discount is applied at Shopify checkout, not as a precomputed product price. Keep the Knit automatic discount **Active** in Shopify admin → **Discounts**.

## Appearance

Logic is only half of the bundle. In the same editor, **Renderer** and **Stylings (CSS)** control how the offer looks and behaves on the product page — layout, copy, and interaction. Change the widget to match the brand. The product sets, conditions, and rewards stay the source of truth for who qualifies and what is discounted.

## Bundle state

Only **Active** bundles appear on the storefront.
