title: "Renderer function"
description: "Register a renderer and paint the widget from the view"
---

The bundle’s **JS code** registers one renderer. The host calls it with a **view** — everything the engine has already worked out — and the renderer turns that view into HTML. It computes nothing.

## Register

Call `defineRenderer` exactly once, at the top level of the script, and declare the view version:

```js
window.nameless.defineRenderer(
  function (ctx) {
    ctx.paint("<div class='nb-bundle'>…</div>");
  },
  { viewVersion: 2 },
);
```

| Rule | Why |
| --- | --- |
| Pass `{ viewVersion: 2 }` | A script with no version is never run. The host logs `RENDERER_VIEW_VERSION_MISSING` and leaves the theme's page as it was |
| Call it at the top level, unguarded | Registration is matched to the loading bundle through `document.currentScript`. A call inside `DOMContentLoaded`, `setTimeout`, or a condition registers against nothing |
| Call it once | One script registers one renderer |

The renderer is registered under the file URL the bundle names, so two bundles that point at the same file share one download. A bundle with no JS code is not drawn; the theme's page stays as it is.

## The context object

| Field | Type | Notes |
| --- | --- | --- |
| `view` | `RendererView` | Read-only. Everything you draw from. See [Renderer view](/renderer-view) |
| `container` | `HTMLElement` | The mount. Already carries `data-nameless-widget="{bundleId}"` |
| `paint` | `(html: string) => void` | Draws your markup into `container` |
| `locale` | `string` | Canonical BCP-47 tag (`"en"`, `"pt-BR"`). Never null |
| `primaryLocale` | `string` | The shop's default language; falls back to `locale` |
| `t` | `(source, vars?) => string` | Translates the copy you write |
| `productUrl` | `(handle) => string \| null` | A product's page in the page's language; `null` where the surface has none |
| `collectionUrl` | `(handle) => string \| null` | The same for a collection |
| `params`, `styleVars`, `customCss`, `widgetCopy` | | Used by the built-in Blueprint widgets. A custom renderer can ignore them |

There is no `dispatch` and no engine state in the context: no conditions, no reward rules, no percentages to read. Don't look for them.

`locale` is the shopper's language on a Shopify theme, the embed's language on a headless surface, and the admin's language in the admin preview. Every price in the view is already formatted for it.

## Paint

Build the whole markup from `ctx.view`, then call `ctx.paint(html)` once.

The renderer runs **many times** — on mount, and after every change to quantity, variant, option, tier, or the cart request. Each call must rebuild everything from the view. Never keep state or DOM nodes between calls.

`paint` morphs your markup into the container rather than replacing it:

- An element with the same `id` stays the same node.
- A `<details>` the shopper opened stays open.
- The control the shopper is typing in keeps its value and focus.

So give every repeated element an `id` built from `view.bundleId` and its own id:

```js
'<li id="nb-' + esc(v.bundleId) + "-row-" + esc(sel.id) + "-" + esc(product.id) + '">'
'<button id="nb-' + esc(v.bundleId) + "-tier-" + esc(tier.id) + '" …>'
```

An element under a new `id` is drawn exactly as written — that is how you open a `<details>` from the view.

`ctx.container.innerHTML = …` also works, but it drops focus, typing, and open panels on every call.

The runtime's listeners live on the container itself, so they survive every repaint. You never wire events — see [Data attributes](/data-attributes).

## Translate your copy

`ctx.t` uses the English source string as the key. There are no key names to invent:

```js
ctx.t("Add to cart");
ctx.t("Add {{count}} more", { count: 2 });
```

It resolves the shopper's language, then the shop's default language, then the literal you wrote. A missing translation shows your literal, never a key or a blank. It never throws.

- Wrap every word you write in `ctx.t`. An unwrapped literal cannot be translated until the renderer is rewritten.
- Text that comes from the view — product, variant, and collection titles, `Money.text` — is already the merchant's. Escape it instead.
- Keep existing `ctx.t` literals byte-for-byte. The literal is the key to the merchant's stored translations; rewording it orphans every language's wording for that string. Change the markup around a literal, not the literal.
- Translate whole phrases with `{{vars}}`. Never concatenate translated fragments — word order differs by language.
- Don't fix widths for labels or buttons. Translated text runs up to 50% longer.
- Write the bundle's title (and a subtitle, if your design has one) as your own `ctx.t` copy. `view.title` is not for drawing.

## Hard rules

| Rule | Why |
| --- | --- |
| No `addEventListener`, no inline `on*=""` | The runtime owns interactivity |
| No `window.nameless.dispatch(...)`, no cart or Ajax calls | State changes come from the [attribute contract](/data-attributes) |
| No `fetch` / `XMLHttpRequest` | Everything you may draw is already in the view |
| No globals, no `localStorage`, no timers that change state | The renderer is a pure function of the view |
| Never cache DOM nodes between calls | Each call rebuilds the markup |
| No arithmetic on money | Print `Money.text`. `Money.amount` exists only to compare two amounts |
| No counting | Unit counts are `view.summary.unitCount` and `selector.summary.unitCount` |
| No eligibility logic | Whether a tier applies, what it saves, and what is missing are all in `view.tiers` |
| Escape every view string | Product titles are merchant input |

Escaping helper — apply it to anything from the view, never to `ctx.t` output (`ctx.t` escapes itself and its variables; escaping twice shows shoppers `&amp;quot;`):

```js
function esc(s) {
  return String(s)
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;");
}
```

## Minimal example

One row per product selector, a total, and an add-to-cart button. Collection rows and tier cards are on [Renderer view](/renderer-view#examples).

```js
window.nameless.defineRenderer(
  function (ctx) {
    var v = ctx.view;
    function esc(x) {
      return String(x)
        .replace(/&/g, "&amp;")
        .replace(/</g, "&lt;")
        .replace(/>/g, "&gt;")
        .replace(/"/g, "&quot;");
    }
    function heading(sel) {
      return sel.itemType === "collection" ? sel.collection.title : sel.products[0].title;
    }
    function variantOf(product, id) {
      for (var i = 0; i < product.variants.length; i++) {
        if (product.variants[i].id === id) return product.variants[i];
      }
      return null;
    }

    var rows = v.selectors
      .map(function (sel) {
        // A collection standing in for the page's product is drawn like a product selector.
        if (sel.itemType === "collection" && !sel.asPageProduct) return "";
        var product = sel.products[0];
        if (!product) return "";
        var picked = sel.selections[0] || null;
        var shownId = picked ? picked.variantId : product.defaultVariantId;
        var options = product.variants
          .map(function (variant) {
            return (
              '<option value="' + esc(variant.id) + '"' +
              (variant.id === shownId ? " selected" : "") + ">" +
              esc(variant.title) + "</option>"
            );
          })
          .join("");
        var price = picked
          ? (picked.eachWas ? "<s>" + esc(picked.eachWas.text) + "</s> " : "") + esc(picked.eachNow.text)
          : esc(variantOf(product, shownId).price.text);

        return (
          '<li id="nb-' + esc(v.bundleId) + "-row-" + esc(sel.id) + '" class="nb-item">' +
          '<span class="nb-item__title">' + esc(product.title) + "</span>" +
          '<span class="nb-item__price">' + price + "</span>" +
          (picked && picked.soldOut ? '<span class="nb-item__badge">' + ctx.t("Sold out") + "</span>" : "") +
          '<select data-nameless-variant-selector="' + esc(sel.id) + '">' + options + "</select>" +
          "<label>" + ctx.t("Qty") +
          ' <input type="number" min="0" step="1" value="' + (picked ? picked.quantity : 0) + '"' +
          ' data-nameless-qty-selector="' + esc(sel.id) + '"></label>' +
          "</li>"
        );
      })
      .join("");

    var hints = v.selectors
      .filter(function (sel) { return sel.pickNeeded; })
      .map(function (sel) {
        return '<p class="nb-bundle__note">' + ctx.t("Choose {{what}}", { what: heading(sel) }) + "</p>";
      })
      .join("");

    var total = v.summary.was
      ? "<s>" + esc(v.summary.was.text) + "</s> <strong>" + esc(v.summary.now.text) + "</strong>"
      : "<strong>" + esc(v.summary.now.text) + "</strong>";

    var atc = v.addToCart.themeButtonAdds
      ? ""
      : '<button type="button" class="nb-bundle__atc" data-nameless-atc="' + esc(v.bundleId) + '"' +
        (v.addToCart.enabled ? "" : " disabled") +
        (v.addToCart.adding ? ' aria-busy="true" aria-disabled="true"' : "") + ">" +
        (v.addToCart.adding ? ctx.t("Adding to cart…") : ctx.t("Add to cart")) +
        "</button>";

    ctx.paint(
      '<div class="nb-bundle">' +
        '<h3 class="nb-bundle__title">' + ctx.t("Build your bundle") + "</h3>" +
        '<ul class="nb-bundle__list">' + rows + "</ul>" +
        hints +
        '<p class="nb-bundle__total">' + ctx.t("Total") + " " + total + "</p>" +
        atc +
      "</div>",
    );
  },
  { viewVersion: 2 },
);
```

## Add-to-cart button

`view.addToCart` drives the button:

| Field | What to do |
| --- | --- |
| `themeButtonAdds` | `true`: the theme's own button adds the bundle. Draw **no** button. The host also removes any stray `[data-nameless-atc]` |
| `enabled` | `false` until something is picked, no pick is sold out, and no row waits for a pick. Disable the button, or keep it pressable and point out what is missing once `pressed` is true |
| `pressed` | The shopper pressed at least once. From then on, name each `pickNeeded` row and each sold-out selection |
| `adding` | The cart request is in flight. Draw the button with `aria-busy="true" aria-disabled="true"` and a spinner or `ctx.t("Adding to cart…")`, keeping its size. The runtime ignores clicks meanwhile |
| `error` | The last press added nothing. Say why near the button: `pickNeeded` → ask for the missing picks; `soldOut` → part of the bundle is sold out; `refused` → print `error.message` (the cart's own sentence, already in the shopper's language) when it is not null, else a general message |

The widget is redrawn on every change, so anything the runtime might write into the button would be lost. Draw the busy and error states yourself from the view — the runtime writes nothing on failure.

`themeButtonAdds` follows the bundle's add-to-cart method. In a popup it is always `false`, because the theme's button opens the popup and the widget's button is the only way to add. Trust the flag; there is no popup case to special-case. See [Shopify integration](/shopify-integration#add-to-cart-method).

## When things go wrong

The host logs structured codes prefixed with `[nameless]`:

| Code | Meaning | Effect |
| --- | --- | --- |
| `RENDERER_THREW` | Your callback threw | Theme elements the bundle hid come back; the container keeps its last paint |
| `RENDERER_LOAD_ERROR` | The CSS fetch or the JS `<script>` failed | The widget does not render for that bundle |
| `RENDERER_VIEW_VERSION_MISSING` | The script declared no `viewVersion`, or never registered | The widget is not run; the theme's page is shown |
| `RENDERER_VIEW_UNSUPPORTED` | The declared version is one the engine does not build | The widget is not run; the theme's page is shown |
| `RENDERER_MOUNT_NOT_FOUND` | No `[data-nameless-block]` element on the page | The renderer is never called |

If the CSS fails, the JS is not run, so treat both assets as required. Stay defensive anyway: guard against empty `selectors`, empty `products`, empty `selections`, `null` images, and `null` money. Write semantic, labelled markup so the widget still works if styling fails.
